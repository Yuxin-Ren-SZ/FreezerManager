# Handoff — SPA hosting security fixes (#44, worker-1)

`freezerd` serves the built SPA from `FMGR_WEB_ROOT`, with same-origin API
requests, a deep-link fallback, and security/cache headers. With the variable
unset, Drogon no longer serves files or implicit pages from its current working
directory. The REST upload memory-body limit now matches the 10 MiB body limit,
so accepted PHI-bearing import bodies do not spill to plaintext temporary files.

**Implementation:**

- `src/rest/StaticAssets.{h,cc}` parses the web root and body limit, sets both
  `setClientMaxBodySize` and `setClientMaxMemoryBodySize`, and disables Drogon's
  default file router and implicit pages unconditionally. The SPA fallback is
  restricted to GET/POST/PUT/DELETE/PATCH; OPTIONS is not reflected by the
  fallback. Canonical path containment rejects traversal and symlink escapes.
  Unknown API paths return JSON 404; security and cache headers are applied to
  gateway responses.
- `src/server/main.cc` installs the fallback after all REST routes are
  registered. The body cap applies even when static hosting is disabled.
- `tests/integration/CMakeLists.txt` excludes only the three Drogon HTTP static
  asset integration binaries under TSan. Pure static path/config unit tests
  remain in the TSan build. No broad TSan suppression is used.
- Linux keeps ASan container-overflow checks and LeakSanitizer enabled. The
  `detect_container_overflow=0` setting is limited to Apple ASan builds because
  local macOS libc++/Drogon teardown reports an upstream container-overflow
  false positive. The client now uses Drogon's IP/port `HttpClient` overload to
  avoid the Linux c-ares URL-resolver leak.

**Regression evidence:** before the fixes, the new preflight test observed the
attacker Origin reflected in ACAO, the disabled-hosting test received planted
cwd `index.html`/JS/TXT files, and the 2 MiB upload test observed a temporary
file while the handler consumed the complete body. Each regression passed
with its corresponding fix in place. The disabled-hosting fixture plants files
in an isolated temporary working directory before Drogon initialization and
restores the original directory after shutdown.
