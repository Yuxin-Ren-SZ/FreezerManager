# Handoff note — 2026-09-29, G0.2 `AuthService.WhoAmI` (#140, worker-2)

The SPA can now ask who is signed in. `AuthService.WhoAmI` (`POST
/api/v1/auth/whoami`) answers with the caller's own identity, the labs they are
a member of **with the role they hold in each**, and the permission keys the
server actually enforces — which is what the shell gates its navigation on. It
did not exist: `grep -rn "WhoAmI" proto/ src/` returned nothing, which is why
`src/web/src/app/App.tsx` still runs on `stubSessionLoader`, a user named "Stub
User" in a lab `lab-1` that is not a UUID (every lab-scoped screen answers
`INTERNAL: invalid UUID length`). Spec: TODO.md G0.2; PRD §7 (RBAC), §10 (web).
Branch `feat/140-whoami`, PR **#146**.

**Changed:**

- `proto/fmgr/v1/auth.proto` — `rpc WhoAmI` plus `WhoAmIRequest` (deliberately
  field-less), `WhoAmIResponse`, `WhoAmIMembership`. Additive; `lock:proto` held.
- `src/server/AuthServiceImpl.{h,cc}` — the handler, and the registration that
  makes it a `TokenAndMfa` RPC rather than a permission-gated one.
- `src/rest/RestGateway.cc` — one route. `src/web/src/api/routes.ts` — the
  matching `auth/whoami` entry (the route checker fails the web job if the
  gateway serves a path the table does not have).
- `src/rpc/ErrorCodes.h` — new, two constants: the `mfa_required: ` marker and
  the `MFA_REQUIRED` envelope code.
- `src/server/GrpcErrorTranslation.h`, `src/rest/RestErrorTranslation.h` — both
  ends of that marker.
- `tests/integration/server_integration_test.cpp`,
  `tests/integration/rest_gateway_integration_test.cpp`,
  `tests/unit/{error_translation,rest_error_translation}_test.cpp`.

**Decisions:**

- **The answer is what the SPA renders, not a dump of the user row.** `labs` is
  the caller's **memberships**, not the labs they can see: a deployment admin's
  `ListLabs` returns every lab, and this must not — the SPA shows "the labs you
  belong to and your role in each", and the demo's blocker B3 ("you are not a
  member of this lab") was exactly a session with one fake lab.
- **Per-lab `permissions` come from the session context**, not from the role
  table. They are the set the gate enforces for this caller, so a client gating
  on them agrees with the server by construction; a role that grants nothing
  still gets its entry, with an empty list.
- **`permissions` at the top level is the deployment-wide set.** Global-only
  grants (`lab.provision`, `backup.run`, …) are promoted to `global_permissions`
  for a SystemAdmin role alone, so they never appear as a lab grant; asserted,
  because that promotion is the one path that differs by role kind.
- **`is_system_admin` is `has_global(lab.provision)`** — the same predicate
  `AuditServiceImpl` and `ShareServiceImpl` spell by hand. This is the **third
  copy** of that two-line helper; a fourth should be one shared function, not
  another copy. Left alone here to keep the diff to one issue.
- **No `session_id`, no expiry.** The issue requires no session id, and there is
  no session expiry to report: `core::Session` has `created_at`, `last_seen_at`,
  `revoked_at` and `mfa_complete`, and the auth layer enforces no TTL. Reporting
  a derived lifetime would have been inventing one.
- **`TODO.md` G0.2 disagrees with the issue, and the issue won.** The plan text
  says a pending-MFA session should *succeed* with `mfa_complete=false` and no
  memberships; #140 requires it to be **refused**. It is refused — a
  half-finished login must not be able to enumerate an identity — and the
  refusal is machine-readable instead (below). If the plan text is meant to win,
  that is a criterion change and belongs on the issue first.
- **`MFA_REQUIRED` exists because #137 asked for it.** worker-1 reported that a
  pending-MFA refusal and an expired session are both `UNAUTHENTICATED`, so its
  session loader would have had to key on the prose `"mfa_required: "`. Now the
  REST envelope says `{"code":"MFA_REQUIRED"}` (HTTP still 401, gRPC code
  unchanged), for **every** MFA refusal, not just whoami. One constant
  (`rpc/ErrorCodes.h`) is read by the producer and the translator, so the two
  ends cannot drift; the unit tests pin both and the integration test pins it
  end to end. Agreed on #137.
- **The response shape is pinned by a descriptor test**, not by a comment: the
  field names of `WhoAmIResponse` and `WhoAmIMembership` are asserted exactly, so
  a later `session_id`/token field fails a test instead of passing review.

New: 5 gRPC integration tests (`WhoAmIListsEveryLabTheCallerBelongsToWithItsRole`,
`WhoAmIDescribesOnlyTheCaller`, `WhoAmIRequestHasNoSubjectField`,
`WhoAmIResponseCarriesNoCredentialOrSessionMaterial`,
`WhoAmIRejectsAbsentAndUnissuedCredentials`), 6 REST gateway tests
(`RestGatewayWhoAmI.*`), 2 REST unit tests, and the marker assertion in
`error_translation_test.cpp`. Three standing tests gained WhoAmI rather than
being left to cover it by hand: the credential-rule pin
(`RpcRegistryStatesTheCredentialRuleEachNonPermissionRpcHas`, now 10 entries),
the pending-MFA boundary test and the permissionless-caller test.

**clang-tidy was run and is not a verdict.** LLVM 17.0.1 against the
AppleClang-generated compile DB cannot complete a frontend here — the SDK's
libc++ trips `no matching function for call to '__countr_zero'`, so the AST is
broken and semantic checks are a different measurement, not a weaker one. Run on
all six changed TUs, **no diagnostic lands on a line this PR adds**; the
findings it reports are in untouched code (`RestGateway.cc:29,37,338,380`,
`core/uuid.h:69`, `core/role.h:84`, `auth/AuthTypes.h:91`, `rpc/RateLimiter.h`,
`obs/Health.h`). CI's `clang-tidy` job is the gate.

**Known limitations / follow-ups:**

- **`npm ci` silently installs no devDependencies when `NODE_ENV=production` is
  exported**, which this shell does. The failure surfaces as
  `gen: buf CLI missing … run npm ci first`, pointing at the wrong thing. #32
  pinned `NODE_ENV` per *script*; `npm ci` itself is still exposed. Worth a line
  in `doc/dev/web.md` or a `--include=dev`.
- **`TODO.md` G0.2 needs the lead's edit** — the response has no `session_id`
  and no `expires_at`, and the pending-MFA paragraph now describes the opposite
  of what shipped.
- **A shared `is_system_admin` helper** (third copy, above) — a tidy-up for the
  lead to file, not part of this issue.
- **Sign-in itself is still G2.1 (#137)**: this RPC only tells a caller who they
  already are. `/login` and `/login/mfa` remain placeholders, and
  `src/web/src/app/stubSession.ts` is still wired in `App.tsx` until that lands.
