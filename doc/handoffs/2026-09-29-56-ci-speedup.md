# Handoff note — 2026-09-29, cut CI wall time (#56, owner session)

The `Build` workflow took 1h35–1h45 per C++ PR, and just as long for PRs that
touched no C++. Two causes dominated: Conan cache misses (37–52 min, 12 of 14 jobs
on the #35/#38 runs) and clang-tidy (25–42 min, run twice). This change targets
~15–20 min for a C++ PR and a minute or two for a docs- or web-only PR. Done in
the owner's session (Claude Code) rather than by a worker. Branch
`ci/56-ci-speedup`.

**Changed:**

- `.github/actions/conan-deps/action.yml` (new) — one composite action for the
  Conan cache, used by the build matrix and by clang-tidy:
  - **One key per build type**, not per compiler. `conan profile detect` runs
    without `CC`/`CXX`, so the clang jobs build their dependencies with gcc 13
    too (`compiler=gcc compiler.version=13` in the clang-17 dev log of run
    36376377466). The per-compiler entries held identical binaries.
  - **Trimmed** with `conan cache clean "*" --source --build --download --temp`
    before saving. Locally, build folders are 9.1 GB of `.conan`'s 15 GB, and
    they were most of each 3.6–3.8 GB CI entry.
  - **Saved only on pushes to `main`**, right after `conan install`, so a later
    build failure or timeout no longer loses it. PR runs restore `main`'s entry
    but never write one of their own.
  - The restore keys still accept the pre-#56 `gcc-13-<type>` /
    `clang-17-<type>` entries, which warm-start runs until they expire.
- `.github/workflows/build.yml`:
  - **`changes` job:** classifies the PR diff (`git diff HEAD^1 HEAD` on
    GitHub's merge commit). If only `src/web/**` (except its `CMakeLists.txt`),
    `doc/**`, `*.md`, `.nvmrc` or `.github/ISSUE_TEMPLATE/**` changed, the build
    matrix and clang-tidy are skipped through job-level `if:`, so they report
    "skipped", which counts as passing. Pushes to `main` always run everything.
    The job also emits the matrix: PRs drop `clang-17 release` (release jobs only
    build; `gcc-13 release` still catches a Release-only break), and `main` keeps
    all seven.
  - **`lint` job:** SPDX and `clang-format-17`, once, without Conan, in about a
    minute. They used to run 7× after the tests, and not at all when a test
    failed. The format check now uses `git ls-files -z | xargs -0`, because
    actionlint's shellcheck flagged the unquoted `$files`.
  - **`clang-tidy` job:** runs once, instead of in both `dev` jobs, with configure
    plus the `freezermanager_proto` target only. It stays at `-j 2`. It uses
    ctcache (commit `857b142`, SHA-256-checked download of
    `clang_tidy_cache.py`, standard library only) with
    `CTCACHE_KEEP_COMMENTS=1`. The cache key is the clang-tidy version; every
    run saves, and the newest entry is restored.
  - The build matrix no longer installs `clang-format-17` / `clang-tidy-17`.
- `doc/dev/clang-tidy.md` — new "In CI" section (what ctcache hashes, why a
  failure is never replayed as clean, how to bypass it for one run, the local
  pip-wheel gotcha).

**Verification (local):**

- `actionlint` 1.7.12 with shellcheck: clean on `build.yml`, including the local
  action's inputs.
- The `changes` job's two scripts, extracted from the YAML and run against 12
  cases: web-only, docs/TODO/README, nested `.md`, issue template + `.nvmrc`
  → skip; `src/web/CMakeLists.txt`, web + one `.cc`, workflow, composite action,
  proto, `conan.lock`, empty diff, push → run. All 12 pass. The PR matrix has
  6 entries; `main` has 7.
- ctcache + LLVM 17.0.6 `run-clang-tidy.py` with `-clang-tidy-binary` on a
  synthetic two-TU compile DB, with a naming check set to error:

  | Step | Result |
  |---|---|
  | Cold run | 2 misses, 2 cached |
  | Warm run | 2 hits |
  | Edit a comment in the shared header | the including TU misses; the other hits |
  | Add a violation | exit 1, not cached |
  | Same violation again | re-checked, exit 1 again |
  | Revert the violation | the original hash hits |

  Each run also has one uncached miss for `run-clang-tidy`'s `-list-checks`
  probe.
- The project's own TUs can't be linted cleanly on this Mac (the pip
  clang-tidy 17.0.1 rejects the newer SDK's libc++ headers), so the real-tree
  run is CI's.

**CI results:** see the PR. The first run is warm through the pre-#56 restore
keys for Debug; it is cold for clang-tidy's result cache.

**Known limitations / follow-ups:**

- The first push to `main` after merge saves the trimmed entries under the new
  keys. Until then, PRs restore the old untrimmed ones (~3.7 GB, about 1–2 min
  to download).
- ctcache entries accumulate stale hashes (a few bytes each) and are never
  pruned; GitHub's 7-day expiry of unused entries bounds this.
- If the Conan cache is ever rebuilt from source, package folder names can change,
  which changes every TU's preprocessed line markers, so the next clang-tidy run
  is cold.
- Not done: ccache and Ninja link pools for the build step. They touch
  `CMakePresets.json`, could save a further 3–6 min per job, and would need their
  own issue.
