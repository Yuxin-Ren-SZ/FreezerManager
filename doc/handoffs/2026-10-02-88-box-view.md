**Decisions:**

- **The grid is drawn from the declared positions, and the holes are cells but
  not positions.** The D4.2 mixed Eppendorf template is a 3×3 block beside a
  2×2 one, so its rectangle is 3×5 with two holes at (2,3) and (2,4): 13
  positions, 15 cells, two `null`. The holes keep the columns aligned and are
  visibly not positions — no label is invented for them (`C4`/`C5` do not
  exist) and nothing can be dropped on them. The `builtBoxGrid` label always
  comes from `BoxPosition.label`.
- **Labels are never derived from `row`/`col`.** The shipped templates number
  rows from **0** (`data/seed/box_types/*.json`) and `src/test/fakeApi.ts`'s
  `seedPositions` numbers them from **1**. An index-to-label convention
  (`String.fromCharCode(64 + row)`) is wrong for one of the two, and the
  divergence is invisible to a test written against only one of them.
- **A sample the box type does not place is reported, not hidden.**
  `grid.unplaced` collects a sample with an empty or unknown `position_label`,
  the second of two rows claiming one position (impossible on the server via
  `samples_position_unique`, possible from a stale cache), and every sample when
  the box type failed to load. The screen says how many there are. A box view
  that silently drops a stored sample is worse than one that admits it cannot
  place it.
- **A tombstoned row is not in the box.** It neither occupies a position nor
  counts as unaccounted for: `sample/list` hides these by default, and the model
  is the guard for a caller that asked for them.
- **One `payload`, one `sample/move` call.** Drag start and Space both set the
  same state; drop and Enter both activate a target cell. The test proves it
  off the wire — two requests, same endpoint, same field set, only
  `dest_position` differing — rather than by asserting on the component's shape.
- **The keyboard is Space to pick up, Enter to put down, Escape to put back.**
  Enter is *not* handled in `onKeyDown`: a browser turns Enter on a focused
  button into a click, so handling both would move twice. Space's default is
  suppressed, which is what stops it becoming a second click. That asymmetry is
  why `BoxScreen.test.tsx` drives the keyboard with `userEvent.keyboard`, which
  models the browser's Enter-to-click translation, instead of a bare
  `fireEvent.keyDown`.
- **The two rejections are two different toasts, and the client does not
  pre-empt either.** `ALREADY_EXISTS` is "that position is taken";
  `INVALID_ARGUMENT` carrying `validate_sample()`'s `container_type size_class
  is not accepted at this box position` is "that container does not fit";
  anything else says only that the move was refused, with
  `apiErrorMessage()`'s translated code. Every cell stays a target, including an
  occupied one: the grid's occupancy is a cache that a live frame may not have
  caught up with, so a move swallowed client-side would be worse than a toast —
  and it is the only way `ALREADY_EXISTS` is reachable from this screen at all.
- **A failed move leaves the sample in hand**, so the next position is one
  activation away; a successful one clears it. A "Put it back" button does the
  same for a mouse user who picked up with Space.
- **No `role="grid"`.** This is a sparse layout with holes, not a rectangle of
  `gridcell`s, and a roving-tabindex grid is more than this issue needs. The
  positions are labelled buttons in a `role="group"` with an accessible name,
  and a free position is `disabled` until something is in hand — otherwise 95
  empty wells are 95 tab stops between the user and the next sample.
- **A cell cannot be both "open the detail" and "put the sample down".** With
  nothing in hand an occupied cell opens the sample; with something in hand
  every cell is a target. Both criteria are in the issue, and this is the only
  reading where they do not fight.
- **The print sheet is always in the DOM and `aria-hidden`.** `@media print`
  hides `.noPrint` and shows `.printSheet`, so the printed page is a stylesheet
  rule and not a second React tree; the map and the label sheet are both built
  from the same `BoxGrid`, so paper cannot disagree with the screen about which
  positions exist. `aria-hidden` because the grid above already exposes every
  position, name and status — 96 more announcements would be noise, not access.
- **Two colour literals in the print block** (`#000` on `#fff`), the only ones
  in the file. Print is not a theme: a dark-mode user must not get white on
  white labels, and `tokens.css` has no print token set. Everything else uses
  the tokens.
- **`src/test/fakeApi.ts` is not touched.** Its `sample/move` resolver already
  models both rejections (`positionHolder` → `ALREADY_EXISTS`;
  `requireAcceptedSizeClass` → `INVALID_ARGUMENT`), so this task needed no
  handler changes at all — the shared file the ASSIGN warned about stayed
  untouched, and this feature's fixtures are built by extending
  `createDemoLab()` in its own test file rather than by editing the seed.
- **The screen moved from `features/layout/` to `features/box/`**, which TODO.md
  G3.4 and the issue both name.

**Known limitations / follow-ups:**

- **`sample/move` cannot express "unplace".** A sample can be moved between
  positions but not taken out of a box from this screen; the request has no way
  to clear `dest_position` distinctly from a position named `""`. The sample
  form (G3.3) has the same limit. A `MoveSample` field mask or an explicit
  "unplace" would be a **proto** change and therefore a `lock:proto` task.
- **Two samples claiming one position are shown one-per-cell at most.**
  `samples_position_unique` makes it impossible on the server; the model reports
  the loser in `unplaced` rather than dropping it, and the screen's warning is
  the only place it surfaces.
- **A box whose type belongs to another lab renders "type unavailable".**
  `box-type/list` is lab-scoped, so a box pointing at another lab's type has no
  positions to draw. That is a data problem for the admin screen (G3.8), and the
  screen says so instead of drawing an empty map.
- **No roving-tabindex arrow navigation**, by choice (see Decisions). 96
  positions is a long Tab walk on a 96-well box; if that becomes the complaint,
  it is a follow-up on this feature rather than a rewrite of it.
- **The print sheet is not covered by a real print engine.** jsdom has no layout
  and does not apply `@media print`, so the guard is a stylesheet assertion plus
  a DOM assertion, and the second half fails if the print block names a class the
  component does not render. A browser check by hand is worth doing before
  anyone relies on the label sheet for a bench.
