# #218 — GetFreezerScene, ListFreezerModels, placement writes, REST (3D-2)

Implemented by: lead (Claude Code), 3D track. Integration branch: `feat/215-layout-3d`.
Design: [ADR 0003](../adr/0003-freezer-3d-layout-api.md) §2–§3. Builds on #217.

## Result

- **`GetFreezerScene`:**
  - Registered `RpcGate::token_and_mfa()`, with a comment, like `GetFreezer`. The handler calls `authenticate(TokenAndMfa)` and then `has_for_lab(freezer.lab_id, SampleRead)`.
  - Unknown or archived freezer: `NOT_FOUND`. Another lab: `PERMISSION_DENIED`.
  - The walk starts at `layout_root_id` and runs breadth-first, parents first:
    - containers in `ordering_index`, name, id order; boxes in label, id order;
    - a visited set is the cycle guard;
    - unreachable containers are never visited (the orphan guard).
  - `occupied_positions` counts non-tombstoned samples with status `active` or `checked_out`. That is the predicate `samples_position_unique` uses.
  - Sample rows stay inside the handler: there's no PHI on the wire and no `phi.read`.
  - `total_positions` is the size of the box type's position list. Archived box types count too.
- **`ListFreezerModels`:** registered `P::SampleRead`, through `authorize(…, SampleRead, lab_id)`. It returns the whole built-in catalogue.
- **Write paths** (`Create/Update{Freezer,StorageContainer,Box}`):
  - An unknown model id gives `INVALID_ARGUMENT`.
  - A placement outside its parent's cells gives `INVALID_ARGUMENT`. The parent's cells are its grid, or for a layout root, `cabinet_bounds` of its freezer's model.
  - A placement under a parent with no grid gives `INVALID_ARGUMENT`.
  - An invalid grid, or a grid on a layout root, gives `INVALID_ARGUMENT`.
  - A sibling collision gives `ALREADY_EXISTS`, from the partial unique index through `UniqueViolation`.
  - A grid change or model change that would strand a placed child gives `FAILED_PRECONDITION`.
  - Update semantics:
    - an absent layout field leaves the stored value unchanged;
    - `clear_placement`/`clear_grid` remove a placement or grid;
    - `freezer_model_id: ""` clears the model.
  - Audit rows are written in the same transaction, as before. The snapshot now carries the new fields; a test pins `placement` in the `after_json`.
- **REST and SPA routes:**
  - `POST /api/v1/freezer/scene` and `POST /api/v1/freezer-model/list`.
  - Both are in `src/web/src/api/routes.ts`, so `check:routes` stays green.

## Notes for #219 (web)

- Call the scene with `call('freezer/scene', { freezerId })` and the catalogue with `call('freezer-model/list', { labId })`.
- `scene.nodes` is parents first, so a single pass can build the render model.
- An absent `model` means: draw the generic cabinet.
- `freezer.freezerModelId` is always present on responses, with `""` meaning none.
