# Handoff note — 2026-09-29, [G2.1] sign-in, MFA and session lifecycle (#137, worker-1)

Issue **#137**: the SPA could not be logged into at all. `src/app/App.tsx` passed
`stubSessionLoader`, which hardcoded a user named `Stub User` in a lab id of
`lab-1` — not a UUID, so every lab-scoped screen answered `internal server
error: invalid UUID length` — and `/login` and `/login/mfa` rendered 19-line
`PlaceholderScreen`s. The screens behind the shell were fine, which the demo
audit established by swapping the stub's lab id for a real one; the session was
the only thing missing. Branch `feat/137-web-session`, PR **#145**.

This slice delivers the sign-in form, the second-factor screen and the whole
session lifecycle against **G0.1's existing browser routes** —
`POST /api/v1/auth/browser/{login,submit-mfa,logout}`. It does **not** deliver
the session loader's body: that is `AuthService.WhoAmI` (**G0.2, #140**), which
does not exist yet. One line of `App.tsx` changes when it lands.

No C++, proto, CMake or workflow file is touched, so CI's C++ matrix and the
`clang-tidy` job are path-gated to *skipped*; the `web` job runs the same
`npm ci && npm run check`. `ctest --preset dev` was therefore not run — there is
no C++ change for it to cover.

**Decisions:**

- **Pending MFA is its own state, and it is not a sign-out.** G0.1 sets the
  session cookie *before* the TOTP code is entered (#62), so a half-finished
  login is real and resumable. `auth::MfaRequired` maps to `UNAUTHENTICATED` —
  the same status as an expired session — so the state has to be carried
  separately. #140 (worker-2) gave it the envelope code `MFA_REQUIRED` next to
  HTTP 401; this branch reads that **and** the `mfa_required: ` message marker
  that predates it, so neither merge order can regress it. `ApiError` carries a
  flag rather than a new `code`, because the gRPC code deliberately stays
  `UNAUTHENTICATED` and no screen's switch has to grow an arm. The two branches
  were written in parallel and could not see each other — this is the one place
  they meet.
- **The MFA screen does not read the refusal, it re-asks the session.** A wrong
  code, an expired session and an already-complete session all answer
  `UNAUTHENTICATED` from `submit-mfa`. Rather than map messages, the screen calls
  `refresh()` afterwards and branches on the *state*: still pending → "that code
  was not accepted", signed out → `/login?expired=1`, a user → go in.
- **`?next=` is an allow-list**, not a deny-list: a same-origin absolute path,
  rejecting `//host` and `/\host` because browsers read both as
  protocol-relative. Unvalidated, the sign-in page is an open redirect.
- **The expiry watcher is status-gated.** `client.ts` reports every
  `UNAUTHENTICATED`, including the ones `Login`/`SubmitMfa` produce for their own
  reasons; only a 401 while signed in means a session ended.

**Known limitations / follow-ups:**

- **The loader is the one blocked line** — `App.tsx` passes a loader that
  resolves `null`, so the app starts on the real sign-in screen instead of
  inventing a user. When #140 merges:
  `const loadSession = createWhoAmISessionLoader(() => call('auth/whoami', {}));`
  The wire shape was checked against #140's branch and matches `WhoAmIWire` field
  for field, so `whoamiSession.ts` needs no change.
- **The initial bundle grew 162.4 → 201.6 KiB gzipped** because the session now
  imports `src/api/client.ts` at app start, and `client.ts` → `routes.ts` →
  every generated proto schema. The budget passes with 48 KiB headroom and both
  kit guards still pass, so this is a note rather than a defect: if a later wave
  grows the entry chunk further, splitting `routes.ts` by domain is the lever.
- Two things this slice deliberately leaves alone: the connection indicator is
  still `'offline'` (it becomes the SSE wrapper's state, G2.2+), and the stale
  `TODO(G2.1)` comment on it in `App.tsx` was kept because the SSE half is not
  done here.
