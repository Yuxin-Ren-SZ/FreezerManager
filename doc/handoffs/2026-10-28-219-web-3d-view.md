# #219 — Web: 3D freezer view on the Layout page (3D-3)

Implemented by: lead (Claude Code), 3D track. Integration branch: `feat/215-layout-3d`.
Design: [ADR 0003](../adr/0003-freezer-3d-layout-api.md) §5. Builds on #217 (types) and #218 (`freezer/scene`).

## Result

- **`/labs/:labId/layout`** now has two tabs, **3D** and **Tree** (`ui/Tabs`).
  - The tree is unchanged. It stays the full text alternative.
  - The tree is the default below 600 px, and wherever `matchMedia` is missing.
  - The choice is remembered in `localStorage` (`fmgr.layout.view`), which is a UI preference (G-arch 7).
- **The 3D tab** draws one freezer from `freezer/scene`, picked from the lab's live freezers. The path is:
  1. open the door;
  2. open an inner door, which can span several levels (TSX);
  3. pull a rack;
  4. follow a box link into the box view (G3.4).
  The rack panel lists every box of the pulled rack, with its cell and fill. Items without a slot are listed under **Unplaced**. A freezer without a model gets a generic cabinet and a note.
- **Engine** (`src/web/src/features/layout/scene3d/`, no dependencies):

  | File | Role |
  |---|---|
  | `iso.ts` | Orthographic yaw/pitch camera, back-face culling, three flat shading bands, painter's sort within explicit layers. The outer shell draws only its outside faces, so it never covers the contents. |
  | `cabinet.ts` | `FreezerModel` → cabinet geometry. `render_key` picks a hand-tuned profile (`cryocube-f740`, `tsx-40086`: base, door depth, panel, rack style). Compartments, slots, inner doors and hinge always come from the model. |
  | `sceneModel.ts` | Scene → racks, cells (box or drawer), loose boxes, unplaced items, counts. |
  | `geometry.ts` | Cabinet + scene + animation frame → blocks, with click targets. Nothing behind a closed door is emitted. |
  | `interaction.ts` | Pure reducer: reaching in opens what's in the way; closing reverses. The home camera looks from the side away from the hinge. |
  | `useSceneFrame.ts` | Tween: parts close before others open. Jumps under `prefers-reduced-motion`, or when there's no `matchMedia` or rAF. |
  | `FreezerFigure.tsx` | The SVG, `aria-hidden` inside an image whose name states what is open. Drag to turn, click a part. |
  | `FreezerScenePanel.tsx` | Picker, data states, controls, rack contents, legend, unplaced list. |

- **Accessibility:** every action in the drawing is also a real control: door button, inner-door select, rack select, turn and front-view buttons, and box links. The drawing needs no keyboard handling of its own. axe is clean with a rack pulled.
- **Style:** flat shading from the design tokens in both themes. Shadows mix towards black, and the dark theme lifts the cabinet off the page. There's no inked look, see-through view or temperature readout (owner decision).
- **Data:**
  - `useFreezerScene` and `useFreezerModels` are in `api/hooks/layout.ts`, under lab-scoped keys.
  - `applySampleFrame` invalidates the lab's scenes, because a move changes box counts.
  - The layout screen does not open its own `sample/watch` stream. Scenes refresh on the next visit, or while another screen's feed is live.
- **Fakes:**
  - `freezer/scene` mirrors the server's walk, counts and `NOT_FOUND`. `freezer-model/list` serves the catalogue. Both support error injection.
  - The demo lab's Freezer A is now a CryoCube F740 with two placed racks; Freezer B has no model.
  - The catalogue's test copy is in `src/test/freezerModels.ts`. The SPA never ships it.
